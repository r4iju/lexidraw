# Private Pro text trial

Ticket #280 adds one bounded continuation tracer (`pro.text`), persistent accounting, and shared web/iOS allowance/history. Public Pro is Coming soon; checkout and payment distribution remain disabled. This does not enable, migrate, or claim protection for existing chat, agent, proxy, image, search, autocomplete or narration entry points. Those need the remaining tickets and #291's full audit. Saved-media playback is unchanged.

## Access and owner tools

Configure `PRO_OWNER_ACCOUNT_IDS` with exact, trusted account IDs from the account database. There is no default owner, email-claim matching, admin-role bypass or client flag. The authenticated Settings owner controls separately grant/revoke eligibility and grant a bounded test period with an explicit reason. An owner also needs eligibility and an allowance to generate. Private eligibility allows the non-secret `{mode:"pro"}` preference; it never creates credits.

All owner mutations use the existing authenticated tRPC transport and its token write-scope checks. `pro.ownerAudit` lists the immutable audit. `pro.ownerOperation({id})` supplies operation/attempt IDs for investigation. `pro.reconcile({id,outcome,evidence})` requires explicit owner authorization and evidence of a completed response, confirmed technical failure, or confirmed cancellation without completion. Do not reconcile based only on age, a missing client, or a timeout. Stop outstanding upstream work and establish its result first. `pro.reconcileAttemptCost({attemptId,costNanoUsd,evidence})` records an invoice-confirmed provider cost independently of customer credits; unexpected higher costs open the spend circuit rather than increasing customer charges. Audit includes the operation/attempt identity and reason.

Private cancellation policy **private-cancellation-v1** is displayed in both clients: stop new paid steps; charge confirmed completed results, even after cancellation or disconnect; release confirmed cancellation with no completion; retain reservations for ambiguous outcomes until owner reconciliation. Technical failures refund the operation. Public cancellation terms remain a separate prelaunch decision. Cancellation/revocation is persisted and checked before every attempt; an active attempt receives best-effort abort, but abort does not establish non-completion.

## Accounting and recovery

The versioned private trial is USD 12/month, 1,000 credits, 1 credit = USD 0.003 reference usage, and 1,000,000 integer subcredits per credit. There is no purchase commitment, annual plan, top-up, rollover, replenishment or overage. Published customer rates are snapshotted on the period and operation. Charges include cached input and total billable output (including reasoning), with rounding only to integer subcredits. UI retains six decimal places.

One text operation reserves at most **1.792 credits** before execution. UTF-8 input is bounded to 1,500 bytes. The complete shared continuation prompt is checked against 4,096 tokens using a conservative byte ceiling and message-framing margin. The tuned server model is `gpt-5.4-mini`; the shared continuation core currently caps generated output at 64 tokens, below the 512-token accounting safety ceiling. No client model, URL, tools or billable settings are accepted. At most two attempts, two concurrent operations, ten operations/minute and thirty seconds per operation are permitted. Five confirmed/unknown failed attempts per minute pause further account attempts. Failure/retry/uncertain exposure is bounded to USD 1 per account period, all attempt exposure to USD 4 per account period, and global attempt exposure to USD 10 per rolling day. These are deliberately conservative private-trial limits, not a measured hosting-cost promise.

Successful provider costs are estimated from actual billable usage and the current provider unit rates, separately from customer reference charges. Failed and uncertain attempts retain conservative maximum exposure when an actual invoice cost is unknown; costs are never silently reported as zero. An invoice can be reconciled through the audited owner tool. Internal retry costs are absorbed. Each paid attempt sends its persisted attempt ID as `X-Client-Request-Id`; confirmed completions persist an allowlisted provider response ID for reconciliation. Explicit regeneration uses a new account-scoped idempotency key; retrying the same request reuses its operation and reservation. Conflicting input under the same key is rejected.

SQLite/libsql write transactions, conditional balance updates, unique account/key and attempt constraints, and immutable ledger/audit/billing-event triggers enforce accounting. Only confirmed SQLite lock failures replay a rolled-back DB-only transaction; network or ambiguous commit failures are not automatically replayed there. Available balance cannot go negative. Settlement releases/debits once against the reserved period, including after renewal. Active old-period reservations remain visible in feature history; the current-period balance never absorbs their debit.

A durable Workflow starts after reservation. Database fences protect provider execution across workflow replay. A crash before the attempt fence can resume; an existing started/unknown attempt cannot dispatch again. A persisted completion can settle after a crash without replaying generation. A confirmed failed attempt can refund after restart. No expiry task frees credits while paid work may still be running. Dispatch failure leaves a recoverable reservation; retry the same `pro.text` input/key. Clients do not own execution lifetime or refund through `finally`.

`ProLedger.consumePurchase(payload, serverVerifier)` is the future sandbox adapter seam for #289/#290. The injected server verifier must authenticate the event/receipt and return only account, source, environment and period identity. It cannot be supplied by API callers. Live events are rejected. Owner test grants and verified sandbox events use the same private period/grant/reservation/settlement contract. Billing-event IDs are persisted and account-bound; duplicate cross-channel events for the same sandbox period create no second allowance. There is currently no configured payment verifier or sandbox checkout; deterministic tests prove accounting, not purchases.

## Local verification and release boundary

Migrations 0015/0016 and their snapshots/journal are committed for deliberate application using the existing migration procedure. They contain only new Pro tables and triggers; unrelated older schema drift was excluded. Do not automatically apply them to a remote database. Ordinary tests use isolated SQLite/libsql databases and injected provider transports, including real SDK HTTP-response fixtures; no production environment or provider key is used. Tests fail closed on unexpected provider networking.

The browser fixture exercises the actual Settings components, authenticated router boundary and isolated local ledger. The native harness can opt into `BROWSER_SCENARIO=pro-shared-local` to read the same loopback ledger and demonstrate cross-client balance/history. It never contacts a provider. These fixtures do not establish authenticated production provider access, tuned model quality, physical-device background behavior or deployed workflow behavior. Local completion does not authorize publication. The whole AI initiative needs one final separately approved release.
