## Problem Statement

Lexidraw's cloud AI features currently use app-owned provider credentials without a shared subscription allowance. Users need a simple way to choose who supplies AI compute without choosing models for individual tasks. The owner needs predictable costs and protection against excessive or repeated requests, including failures that still incur provider charges.

Pro cannot be offered publicly yet. The owner and approved testers nevertheless need to exercise its real entitlement, credit, and billing behavior now, without charging customers or exposing app-owned APIs to everyone.

BYOK users must not entrust provider credentials to Lexidraw's servers. Generation can happen on their devices while finished artifacts, such as recordings, sync through account-owned storage. The architecture needs to share generation logic without routing user keys through a backend proxy.

## Solution

Provide one tuned AI experience with three account-level power choices: Pro, a single supported provider key supplied by the user, or built-in local device capabilities. Do not expose a model picker or Fast/Intelligent modes. Internally choose and tune models for each capability. Pro executes on our servers with app-owned credentials; BYOK executes on the user's device with device-held credentials; local executes through built-in device capabilities. Share platform-neutral generation logic through TypeScript and inject runtime-specific provider, credential, execution, and artifact-storage adapters.

Keep the core app and available built-in local AI free. Local iOS narration must use Apple's built-in speech synthesis. Apple Intelligence is a separate local text capability and must be offered only where the device, OS, language, and API support it. Unsupported local features remain clearly unavailable.

Publicly show Pro as **Coming soon**, with purchases and access disabled. Allow the owner and explicitly approved testers to exercise Pro through server-controlled private access, test entitlements, and sandbox billing. UI visibility, private eligibility, payment environment, and entitlement are distinct controls. No live customer payments are enabled by this spec.

Pro has one account-wide monthly AI credit allowance shared across web and iOS. Credits expire at renewal, do not roll over, and cannot be topped up. There are no automatic overages. When credits run out, new Pro cloud generation stops; BYOK, local capabilities, and playback of saved audio remain available.

## Implementation Decisions

- **Account contract:** store an account-level preferred power source and, for BYOK, one selected supported provider. The same non-secret account preference is used across clients; key presence and local capability availability are evaluated on the current device. Device setup never syncs the secret. Do not introduce per-feature provider configuration or consumer model controls. Use explicit choices when a capability is unavailable, with no implicit cloud or system-key fallback.
- **Private release gates:** retain a public Coming soon state and disable live checkout. Private eligibility is a server-owned allowlist or equivalent explicit grant for the owner and approved testers. Eligibility alone is not an entitlement: test access requires a bounded test entitlement. Ordinary admin status, a client flag, an arbitrary email claim, or a hidden URL must not automatically authorize Pro.
- **Payment environments:** test grants and sandbox purchases feed the same entitlement and ledger behavior used by future live billing, while remaining clearly marked and isolated from live purchase events. Never accept an unverified client claim or a sandbox receipt as a live payment. Account identifiers, not shared tester credentials, identify participants.
- **Trial pricing:** configure USD 12/month and 1,000 credits per billing period as initial private-trial values, not final public commercial terms. No annual plan, credit packs, rollover, or automatic overages. Monthly successful-generation reference cost is approximately USD 3; a separate USD 1 retry/delivery envelope is an economic assumption to validate, not a guaranteed spending ceiling.
- **Credit price book:** use a versioned reference price book with an initial conversion of one credit per USD 0.003. Track actual provider invoice cost independently. Publish understandable feature rates and quotes, pin accepted-operation rates, and keep customer rates stable through their current period. Include known provider price changes in the launch configuration. Preserve fractional usage as integer subcredits and round only for display.
- **Curated models:** internally choose one tested configuration per capability. Validate provider access, exact model identifiers, supported parameters, quality, and billable usage before enabling a capability. The current defaults include deprecated or older preview models; do not price or substitute them based on unverified alias assumptions. Supported BYOK providers must pass a one-key text/image/narration capability check; present honest availability when coverage is incomplete.
- **Shared logic and execution:** introduce one platform-neutral TypeScript generation core for preparation, prompts, chunking, orchestration, and result processing. Inject constrained adapters for provider transport, opaque credential references, persistence, execution lifetime, and artifact sync. Pro runs this logic server-side; web BYOK runs it in the browser. Native iOS uses a bundled JavaScript runtime with a constrained native bridge for networking, Keychain, files, and task lifecycle. Keep native credentials outside serialized JavaScript job state; native transport attaches them immediately before provider requests. Validate the bridge with a direct-generation tracer before enabling native BYOK; if a capability cannot run safely, mark it unavailable rather than silently moving it to the server. Built-in local APIs are native adapters, not cloud provider shims.
- **Pro operation boundary:** centralize server-side entitlement, quotes, reservations, bounded execution, and settlement for app-owned paid calls. Chat, generation, autocomplete, agent planning/decisions, images, cloud narration, and paid search use this contract. A Pro agent action includes internal model calls and paid tools under one bounded parent operation. BYOK does not submit keys to that operation API or debit its ledger.
- **BYOK capability coverage:** a single device-held key supplies the capabilities its chosen provider supports. Do not silently use our Google search key or another provider credential for a BYOK tool. Unsupported tools, including paid search lacking a direct authorized implementation, remain unavailable with an explanation. Cross-origin browser access, provider permission requirements, and native direct access are capability validation gates; no permissive server proxy is an escape hatch.
- **Legacy proxies:** eliminate arbitrary provider-path forwarding under app-owned credentials. Move Pro client-side agent work onto bounded server operations and BYOK work onto approved direct-device transports before removing the forwarding route; retain no alternate unmetered path. Never repurpose the proxy to receive user keys. Restrict model, endpoint, output, and tool settings on the server.
- **Persistent accounting:** introduce verified entitlement records, billing periods, immutable ledger entries, operations with account-scoped idempotency keys and price snapshots, reservations, provider attempts, and audited private-access grants. Available credits equal the period grant minus settled charges and active reservations. Atomic reservation and settlement must survive simultaneous web/iOS calls.
- **Terminal outcomes:** settle each operation at most once, or refund it on technical failure. Completed results consume credits; explicit regeneration is a new operation. Internal retries are absorbed. Record failed attempts and provider charges even when customer credits are refunded.
- **Pro durability:** carry account, entitlement, operation, and reserved-period identity through server narration and agent workflows. Retry steps idempotently; reconcile uncertain provider outcomes before replaying paid work. A timeout cannot release a reservation while its job may still be spending. Running old-period operations settle against the original period after renewal.
- **BYOK interruption and resumption:** persist non-secret progress and completed output parts on the device, with optional finished-artifact sync. Never serialize a key into a job, queue, resume checkpoint, or server payload. Browser closure or OS suspension can pause/interrupt generation; show the actual state and resume from usable completed parts after credential availability is re-established. Reconcile uncertain provider outcomes instead of promising exactly-once provider billing. Local progress is not a durable server execution guarantee. Deletion/replacement of a key invalidates queued credential references; best-effort cancellation cannot undo an already issued provider request.
- **Streaming and cancellation:** reconcile provider completion on the server even if the client disconnects. Technical failures, including failed streams, refund the operation. Explicit cancellation stops further work and must have a disclosed settlement policy distinct from technical failure. The precise cancellation charge policy remains a pre-launch decision and is not silently inferred from an error code.
- **Narration reuse:** preserve existing saved audio and useful cached parts. Replaying generated audio is free of generation-credit charges. Quotes cover only synthesis still required. Failed narration operations are refunded even if some parts were delivered; retained parts must not produce double charges on retries. Avoid cross-account ownership or privacy leakage through caching.
- **Device credential custody:** use native iOS Keychain for BYOK keys with device-only, non-synchronizing storage and browser session memory by default. Do not add localStorage, IndexedDB, cookie, server-secret-store, database, or cross-device secret persistence. Provider validation happens directly on the device. Account settings may sync provider identity and preferred mode but never raw, encrypted, encoded, or otherwise recoverable key material. Replace/delete controls clear local references and stop new use; logout clears web in-memory keys. BYOK provider billing remains the user's responsibility and never consumes Pro credits.
- **Credential egress contract:** represent BYOK secrets as opaque references available only to the provider transport, not general job/configuration objects. The transport attaches a key only at the final request boundary to an exact approved HTTPS provider origin and approved API path. Users cannot set arbitrary base URLs. Reject provider redirects for authenticated calls rather than forwarding credentials. Account tokens, signed upload grants, and Pro keys have separate types and scopes from BYOK secrets.
- **Runtime assertions:** all app-origin, storage-upload, telemetry, diagnostic, and error-reporting transports must reject known configured BYOK key values before sending any headers, URL parameters, body, or metadata. Add defense-in-depth provider-key pattern checks without relying on patterns as the only control. Cover fetch/XHR, beacon/reporting paths, native networking, uploads, and bridge serialization. Use strict data allowlists; do not spread provider configuration, raw errors, request/response envelopes, or SDK objects into app requests. On rejection, emit a fixed non-secret error, never the matched value. Errors and provider output must be sanitized/checked before logging or syncing, including artifact content that could echo a credential. Build-time boundaries keep provider-key attachment confined to approved transports. These controls enforce the app's supported paths; they are not a claim that an arbitrary encoding scanner proves the absence of every possible secret.
- **Artifact sync:** device generation uploads only generated content and allowlisted recording/document metadata using account-authenticated upload authorization. Storage never receives BYOK credentials. Validate ownership, content type, size, quotas, and expiry, then register the finished artifact under its account/document with idempotent finalization. Keep uploads private according to existing document access rules and remove abandoned parts. Recordings can sync to another device that has no key. Upload/storage failures retain completed local output for retry; they must not trigger provider regeneration unnecessarily. Storage traffic remains bounded even though BYOK generation does not consume Pro credits.
- **Local execution:** integrate native iOS speech synthesis with reading position, playback controls, background audio, and interruption handling. Separately detect and integrate supported Apple Intelligence text capabilities. Local failures do not silently invoke cloud services; unsupported images/search/narration capabilities are explained. The first release does not connect external local-model servers.
- **Usage UI:** show power source, capability availability, balance, reserved amount, renewal date, and feature usage history. Explain exhaustion and Coming soon states without exposing implementation details. Autocomplete is opt-in and metered in aggregate with one outstanding request and cancellation of superseded work.
- **Cost and abuse bounds:** apply account-wide burst/concurrency limits, per-operation input/output/duration/tool/agent-cycle ceilings, bounded internal retries, and provider-spend circuit breakers. Start private testing with one active agent run, one narration job, two image operations, two interactive text operations, and one autocomplete request per account; tune from observed behavior. Device/network controls supplement account limits. Refunded failures still count toward request and failure limits.
- **Billing reconciliation:** process sandbox subscription creation, restore, renewal, cancellation, expiry, refunds/revocations, and payment failure idempotently and in event-time order. Avoid duplicate grants across purchase channels. Future live integration must preserve account-wide entitlements while keeping sandbox and live events separate.
- **Migration:** stop ordinary accounts from initiating unentitled system-key work once the private gate is enabled, with a clear UI explanation and BYOK/local alternatives. Preserve core documents, drawings, saved audio, and existing user data. Determine existing-user communication and staged rollout before enforcement reaches production.
- **Release boundary:** implementation and private testing are deliverables now. Public checkout, live charges, and public activation require a separate deliberate launch; completing this issue does not enable them.

## Testing Decisions

- The user confirmed the revised seams: the **authenticated AI operation boundary for Pro**, **client network interception for BYOK credential egress**, and supplementary end-to-end web/iOS checks. Replace server-side BYOK key-selection tests with outbound client-network assertions. Exercise the shared generation contract through injected adapters instead of duplicating algorithm tests across runtimes.
- Exercise real entitlement/ledger persistence with deterministic provider adapters and a controlled clock. Assert the returned result, availability, credits, provider invocations, and durable operation outcome, not private helper calls or internal method ordering.
- Verify public Coming soon accounts cannot start system-key work or live checkout, including direct requests, forged client settings, old proxy routes, and delegated sandbox tool calls. Verify approved testers need an entitlement, and revoked accounts cannot start new work.
- Verify power selection for every capability: Pro uses only server-approved credentials with authorization; BYOK device traffic reaches only the selected provider with that device's key; local invokes no cloud provider. Invalid keys, unavailable direct browser access, absent native runtime support, and unsupported local capabilities never fall back to a proxy or system keys.
- Intercept all relevant client egress using distinctive fake OpenAI, Anthropic, OpenRouter, and other supported provider credentials. Confirm the intended credential reaches only its approved provider origin/path, and app APIs, owned buckets, analytics, error reporters, redirects, and bridge payloads receive none of it. Cover query/header/body/metadata mistakes, JSON serialization, raw SDK errors, provider output echoing keys, encoded accidental representations, uploads, and removed/replaced keys. Deliberately attempt bad requests and prove rejection happens before dispatch. Secret values must not appear in logs or error responses. A key-format test is not a promise of provider feature support.
- Verify device-only persistence and lifecycle: iOS Keychain entries are non-synchronizing; web keys disappear after session lifecycle termination and logout; account API schemas and stored preferences contain no key material. Repeat the outbound assertions through native transport/bridge and web transports, not only a mock credential resolver.
- Verify device generation, interrupted/resumed chunk processing, uncertain provider outcomes, local artifact retention after upload failure, idempotent upload finalization, account ownership, abandoned-part cleanup, and playback from a second device without a key. Unsupported direct access must produce an unavailable state with no backend-provider request.
- Verify fractional accounting, quoted ceilings, exact exhaustion, concurrent reservation near zero balance, repeated requests, duplicated workflow steps, settlement retries, technical-failure refunds, provider uncertainty, and old-period work completing after renewal.
- Verify whole-action Pro accounting for agent planning, decisions, tools, and generation, including step-cap stops and partial-edit reporting. Verify narration chunk reuse, failed jobs, retry recovery, and free replay after exhaustion. Verify equivalent BYOK actions execute on-device without Pro debits, while unsupported paid tools never use our credentials.
- Verify stream disconnects, explicit cancellation, request/concurrency limits, retry bounds, and circuit breakers. Failures must remain bounded even when credits are refunded. Separate customer ledger assertions from actual provider-cost assertions.
- Verify sandbox billing signatures/receipts and duplicated/reordered events, grants, renewal, restore, cancellation, expiry, failure, refunds/revocations, and cross-channel duplicates. Prove sandbox events cannot create live entitlements and live checkout remains disabled.
- Prior art includes authenticated router callers with a test database and durable-workflow start interception, narration workflow retry/reuse tests, API authorization tests, agent request tests, provider error-classification tests, and native listening-position tests. Reuse those fixtures at the shared operation seam where possible.
- End-to-end scenarios cover ordinary-account Coming soon, tester access, device-local BYOK connect/replace/remove, per-device key setup, direct generation and artifact sync, capability availability, quotes, balance/history, exhaustion, and a web/iOS shared Pro balance. Native-device checks cover local narration, background/locked-screen audio, controls, interruption/recovery, and unavailable Apple Intelligence behavior.
- Write meaningful accounting and authorization tests first and verify they fail before implementation, following the repository's testing preference. Use sandbox payments and bounded private provider smoke tests for external integration; ordinary CI must not generate paid provider usage.

## Out of Scope

- Public Pro activation, production checkout, or charging customers.
- Unlimited cloud usage, free cloud AI allowances, credit top-ups, rollover, annual plans, or automatic overage billing.
- User-facing model selection, speed/quality tiers, multiple simultaneous BYOK providers, and per-feature key configuration.
- Connections to Ollama, LM Studio, or other external local-model servers at launch.
- A promise that local mode supports every cloud capability or that Apple Intelligence and built-in speech synthesis are the same service.
- Team/org/shared-account billing, seats, enterprise invoicing, and transferable credits.
- Server custody, cloud backup/sync, backend proxying, or background server execution of user-supplied provider keys, including encrypted or encoded copies.
- Persistent browser-key storage, arbitrary user-supplied provider base URLs, and promises of uninterrupted device generation after app/browser shutdown.
- A promise that scanning key patterns detects all possible encodings or that arbitrary third-party scripts/device compromise are prevented by network assertions alone.
- Final public pricing, exact public operation rates, guaranteed quantities of messages/images/listening hours, and a guaranteed net margin before measurement.
- Changing the unrelated App Store review resubmission already completed in this conversation.

The user selected device-side BYOK with shared generation logic and requested assertions that user provider keys never reach our infrastructure. Revised test seams were explicitly confirmed on 2026-10-10. Private-only Pro and public Coming soon, together with the previously agreed credit rules, remain in scope.

The previous twelve-ticket breakdown was a proposal and was not approved or published. It must be rebuilt from this spec: server secret storage and server-side BYOK generation are no longer deliverables. Keep the existing issue identity and ready-for-agent label, rather than creating a competing spec.

Commercial trial figures are based on provider list prices, not measured production behavior. A conservative 30% distribution fee leaves USD 8.40 from a USD 12 subscription; subtracting the assumed USD 4 variable-cost envelope leaves USD 4.40 before fixed costs, tax, and support.
